# 更新時のメモ

## バージョン更新

`package.json` の `version` は手で書き換えず、npm のバージョンコマンドで更新します。

```bash
npm version patch   # 0.1.0 → 0.1.1: バグ修正など、後方互換性のある変更
npm version minor   # 0.1.0 → 0.2.0: 後方互換性のある機能追加
npm version major   # 0.1.0 → 1.0.0: 破壊的変更
```

npm が `package.json` と `package-lock.json` のバージョンを一緒に更新します。通常の設定では、バージョン更新と同時に Git のコミットとタグも作成されます。そのため、先に作業内容をコミットし、作業ツリーが clean であることを確認してから実行します。

```bash
git status
npm version patch
```

変更の影響に合わせて `patch` / `minor` / `major` を選びます。コミットの種類だけでバージョンを機械的に決めるのではなく、公開済み機能との互換性を基準に判断します。

## コミットメッセージ

コミットメッセージは、変更内容が分かる短い要約にします。次の形式にそろえると履歴を探しやすくなります。

```text
種類: 変更内容
```

| 種類 | 用途 | 例 |
| --- | --- | --- |
| `feat` | 機能追加 | `feat: 依頼一覧に検索を追加` |
| `fix` | 不具合修正 | `fix: ログイン後に画面が更新されない問題を修正` |
| `docs` | ドキュメント変更 | `docs: 更新手順を追加` |
| `update` | 内容を具体化しにくい更新 | `update: 依存パッケージを更新` |
| `chore` | 開発環境や保守作業 | `chore: lint設定を整理` |
| `refactor` | 振る舞いを変えない内部整理 | `refactor: 通知処理を分割` |

`add` は Git の `git add`（コミット対象としてステージする操作）と混同しやすく、コミット種別としては `feat` のほうが機能追加を明確に表せます。ドキュメントの種別は `dock` ではなく `docs` を使います。`update` は範囲が広くなりやすいため、可能なら `feat`、`fix`、`docs` など変更の目的に合った種類を選びます。

```bash
git add app/page.tsx
git commit -m "feat: 依頼一覧に検索を追加"
```

このプロジェクトではメッセージ形式は強制されていませんが、上記の表記を目安に統一します。
